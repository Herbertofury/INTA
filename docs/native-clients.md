# Native Desktop and Mobile clients

The [native client crate](../crates/inta-native/) implements the technician reference workspace directly in [Rust](https://www.rust-lang.org/). Desktop and <a href="https://source.android.com/docs/security/bulletin" title="Open source.android.com official download or service page" aria-label="Open source.android.com official download or service page" data-inta-brand="site-source-android-com"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/a0ebdc99aa893f3365ec.png" alt="source.android.com official page" width="18" height="18" valign="middle" /></a> [Android](https://source.android.com/docs/security/bulletin) Mobile share the same application source, catalog identities, search behavior, checklist identities and persistent-state model. It uses native <a href="https://github.com/" title="Open GitHub official download or service page" aria-label="Open GitHub official download or service page" data-inta-brand="app-github"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/99f4edb33272b70febb8.png" alt="GitHub official page" width="18" height="18" valign="middle" /></a> [egui](https://github.com/emilk/egui) controls and rendering; it does not embed the Site in a WebView.

## Implemented working surfaces

- **Tool library first, then Online tools.** Search the complete catalog and compose category, platform, recommendation and access-mode filters. Choose list or gallery without changing results. Sort by name, recommendation, review date or independently observed provider metrics; unknown evidence remains unknown and sorts last.
- **Direct tool actions.** Every tool keeps its official page and acquisition routes; details include supported platforms, pricing, cautions, documentation, source provenance, observed reputation data and related guides. Online entries retain first action, expected result, account boundary, submission behavior and official evidence.
- **Playbooks and checklist.** All complete procedures, scenario quick answers, authored tool choices, working tools, manufacturer/resource links, diagnostic decisions, stopping conditions, verification checks, specific fixes and command references remain available. Progress uses the shared Rust checklist identity/migration functions. Start-fresh confirmation, current-state <a href="https://github.github.com/gfm/" title="Open Markdown official download or service page" aria-label="Open Markdown official download or service page" data-inta-brand="app-markdown"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/99f4edb33272b70febb8.png" alt="Markdown official page" width="18" height="18" valign="middle" /></a> [Markdown](https://github.github.com/gfm/) export and clipboard export are implemented.
- **Command Center and maintenance.** Search and filter shell, category and impact. Copy commands or complete workflows, inspect their warnings and official references, and distinguish OS, application and package-manager channels. Copying does not execute a command.
- **News and references.** Read the bundled dated source snapshot, open publisher links, save/read articles, filter selected sources and browse the complete source directory. No background refresh or polling is performed. The service map, knowledge desk and official-reference search remain available.
- **Portable local state.** Favorites, layout, filters, checklist state and news selections survive restart. Dark is the default, with a complete light appearance and navigation that reflows for narrow windows.

These are the public reference and local-progress surfaces. Account login, authenticated device enrollment, fleet/job synchronization, remote phone-to-PC actions, shared timers and billing are separate ecosystem milestones. Local persistence does not claim those capabilities or create a live host connection. The maintenance agent is separately implemented and must complete its applicable integration gates before native UI claims live execution.

## Desktop data and relocation

By default the application places `INTA-Data` beside its executable. The folder contains a stable workspace-identity manifest and `native-state.json`; exported checklists go into its `exports` directory. The executable and folder may move together without depending on the executable's name. A valid optional `catalog.json` in this directory supplies the public catalog; otherwise the complete bundled edition is used.

Set `INTA_DATA_DIR` to select an explicit location. If the executable directory is read-only, the application reports that state uses the operating system's user data directory and displays the actual location in Resources. It does not claim portable behavior for an unwritable directory. An unreadable state file is preserved before a new state is created; saving errors are shown. Keep customer-specific notes and credentials outside this public reference catalog.

<a href="https://source.android.com/docs/security/bulletin" title="Open source.android.com official download or service page" aria-label="Open source.android.com official download or service page" data-inta-brand="site-source-android-com"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/a0ebdc99aa893f3365ec.png" alt="source.android.com official page" width="18" height="18" valign="middle" /></a> [Android](https://source.android.com/docs/security/bulletin) uses the platform's app-private data directory. That location is not a user-movable portable Desktop folder. The same state schema and shared stable checklist keys apply.

## Build and run

```sh
cargo test --locked -p inta-ui -p inta-native --lib
cargo run --locked -p inta-native --bin inta-desktop
cargo build --locked --release -p inta-native --bin inta-desktop
```

Command legend: [Cargo](https://doc.rust-lang.org/cargo/) builds and tests the shared [Rust UI](../crates/inta-ui/) and [native client](../crates/inta-native/). The Desktop binary is `target/release/inta-desktop`, with the `.exe` suffix on <a href="https://www.microsoft.com/windows" title="Open Windows official download or service page" aria-label="Open Windows official download or service page" data-inta-brand="app-windows"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Windows official page" width="18" height="18" valign="middle" /></a> [Windows](https://www.microsoft.com/windows).

The [native client workflow](../.github/workflows/rust-clients.yml) builds <a href="https://www.kernel.org/" title="Open Linux official download or service page" aria-label="Open Linux official download or service page" data-inta-brand="app-linux"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/c274b9b1ea45948db04e.png" alt="Linux official page" width="18" height="18" valign="middle" /></a> [Linux](https://www.kernel.org/) and <a href="https://www.microsoft.com/windows" title="Open Windows official download or service page" aria-label="Open Windows official download or service page" data-inta-brand="app-windows"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Windows official page" width="18" height="18" valign="middle" /></a> [Windows](https://www.microsoft.com/windows) executables, packages each with the catalog and this guide, and records SHA-256 sidecars through the existing Rust package utility. Its <a href="https://www.kernel.org/" title="Open Linux official download or service page" aria-label="Open Linux official download or service page" data-inta-brand="app-linux"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/c274b9b1ea45948db04e.png" alt="Linux official page" width="18" height="18" valign="middle" /></a> [Linux](https://www.kernel.org/) run captures actual rendered desktop, narrow-window and job views under a virtual display. ## Proof and acceptance

The native unit tests exercise full catalog identity preservation, independent metric ordering, composed search/saved filters and portable-state round trips. The shared UI tests cover stable checklist migration, full guide/resource/fix coverage, scenario-specific acquisitions and current-state exports.

Use build, locally tested, device-tested and published precisely. A successful <a href="https://www.kernel.org/" title="Open Linux official download or service page" aria-label="Open Linux official download or service page" data-inta-brand="app-linux"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/c274b9b1ea45948db04e.png" alt="Linux official page" width="18" height="18" valign="middle" /></a> [Linux](https://www.kernel.org/) compile does not prove <a href="https://www.microsoft.com/windows" title="Open Windows official download or service page" aria-label="Open Windows official download or service page" data-inta-brand="app-windows"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Windows official page" width="18" height="18" valign="middle" /></a> [Windows](https://www.microsoft.com/windows) native behavior, an APK build does not prove phone input or lifecycle, and neither proves account synchronization. Record the exact package checksum, source revision and device/OS with the applicable runtime results. The full [four-lane acceptance gates](ecosystem-development.md) remain in force.
