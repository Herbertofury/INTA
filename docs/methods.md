# 🧠 Methods that turn symptoms into proof

[Home](https://github.com/Herbertofury/INTA/wiki) › **Methods**

**Choose a method by the question it answers.** A tool collects or changes something; a method explains why that action is useful and what evidence should change the next step. Open a linked method to reach its complete field guide.

The registry contains **40 named methods**: a method for each of the **22 job guides**, plus **18 reusable diagnostic concepts**. These are INTA operating methods supported by the linked platform sources. They are not a claim that every technique was invented, standardized or independently benchmarked here.

## 🛟 Protect and regain control

| --- | --- | --- |
| [Structured intake and triage](https://github.com/Herbertofury/INTA/wiki/Job-intake-triage) | Use at the beginning of a job or when ownership changes. | Exact failure, affected scope, protected data and next action are recorded. |
| [Incident containment](https://github.com/Herbertofury/INTA/wiki/Job-ransomware-response) | Use for active encryption, wider compromise or credible spreading-threat evidence. | Isolation, incident ownership, affected scope and controlled reconnection criteria are recorded. |
| [Image-first recovery](https://github.com/Herbertofury/INTA/wiki/Job-failing-drive) | Use for repeated I/O errors, disappearing drives or credible physical-failure evidence. | Source identity, image, mapfile, unreadable regions and recovered-file usability are recorded. |
| [Dependency-ordered outage recovery](https://github.com/Herbertofury/INTA/wiki/Job-outage-recovery) | Use after an office power failure or a multi-service interruption. | A client workstation completes the real business workflow and degraded dependencies have owners. |
| [Windows startup recovery](https://github.com/Herbertofury/INTA/wiki/Job-boot-recovery) | Use when the operating system will not start normally. | The intended installation boots repeatedly with data, encryption and applications intact. |

## 🧩 Narrow the uncertainty

| Method | When it helps | What proves progress |
| --- | --- | --- |
| [Scope isolation](https://github.com/Herbertofury/INTA/wiki/Job-intake-triage) | Use when the symptom is vague or reported as affecting everything. | A failing and a working comparison establish the next investigation boundary. |
| [Known-good comparison](https://github.com/Herbertofury/INTA/wiki/Job-intake-triage) | Use when an interchangeable component can distinguish likely causes. | The compared conditions and the result for both paths are recorded. |
| [Single-change experiment](https://github.com/Herbertofury/INTA/wiki/Job-slow-pc) | Use when several explanations could fit the current evidence. | The predicted result, actual result and rollback are recorded before another variable changes. |
| [Reproducible baseline](https://github.com/Herbertofury/INTA/wiki/Job-slow-pc) | Use before claiming a repair or performance improvement. | Another technician can repeat the same workload and compare equivalent observations. |
| [Timestamp correlation](https://github.com/Herbertofury/INTA/wiki/Job-hardware-bsod) | Use for intermittent crashes, update failures or incidents. | Timezones, clock uncertainty and the supporting sequence are recorded. |
| [DNS-versus-connectivity isolation](https://github.com/Herbertofury/INTA/wiki/Job-network-dns) | Use when an address works but a name fails, or different resolvers give different results. | The failing layer is identified without replacing organization-specific DNS blindly. |

## 📚 Sources and evidence boundaries

Each method record retains its exact destination, aliases, purpose, use conditions, proof and original sources in [the method registry](https://github.com/Herbertofury/INTA/blob/main/data/methods.json). The full field guides retain their own source lists and escalation boundaries.

- [Microsoft: recovery options](https://support.microsoft.com/en-us/windows/experience/backup-recovery/recovery-options-in-windows) supports the documented recovery choices.
- [GNU ddrescue manual](https://www.gnu.org/software/ddrescue/manual/ddrescue_manual.html) supports the imaging and mapfile workflow used in [image-first recovery](https://github.com/Herbertofury/INTA/wiki/Job-failing-drive).
- [restic restore documentation](https://restic.readthedocs.io/en/stable/050_restore.html) supports the recovery mechanics used in [restore verification](https://github.com/Herbertofury/INTA/wiki/Job-backup-restore).
- [Microsoft: Get-FileHash](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.utility/get-filehash) and [Get-AuthenticodeSignature](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.security/get-authenticodesignature) support the local checks used in [publisher and checksum verification](https://github.com/Herbertofury/INTA/wiki/Job-boot-usb). A matching digest by itself does not establish an independent trust root.
- [Microsoft: recovery-key lookup](https://support.microsoft.com/en-us/windows/security/encryption/find-your-bitlocker-recovery-key) supports [BitLocker recovery readiness](https://github.com/Herbertofury/INTA/wiki/Job-boot-recovery).
- [Microsoft: DNS client troubleshooting](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/troubleshoot-dns-client-resolution-issues) supports [DNS-versus-connectivity isolation](https://github.com/Herbertofury/INTA/wiki/Job-network-dns).
