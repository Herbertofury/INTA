## 🧭 Match the symptom

| You see this | Do this next | You should get |
| --- | --- | --- |
| **A [Windows](https://www.microsoft.com/windows) user is present and can approve a session** | Open <a href="https://apps.microsoft.com/detail/9P7BP5VNWKX5" title="Open Microsoft Quick Assist official download or service page" aria-label="Open Microsoft Quick Assist official download or service page" data-inta-brand="quick-assist"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Microsoft Quick Assist official page" width="18" height="18" valign="middle" /></a> [Microsoft Quick Assist](https://learn.microsoft.com/en-us/windows/client-management/client-tools/quick-assist) on both PCs, exchange the temporary code and have the user approve sharing and any separate control request. | The correct screen is visible and the user understands the control state. |
| **The task requires unattended access or durable audit records** | Use the approved managed tool and existing device identity; verify the technician’s role before connecting. | The session is tied to the intended asset and required audit record. |
| **Elevation or a secure-desktop prompt blocks work** | Have the authorized local user respond or use the approved managed elevation workflow; do not ask for credentials in chat. | The required action is approved without disclosing credentials or bypassing consent. |
| **The repair appears complete** | Repeat the original task with the user, end the session and remove any case-only access setting. | The user confirms the outcome and temporary control has ended. |

### ✅ Finish the job

- [ ] The original task works in the user’s session.
- [ ] The session is closed and authorized persistent access is documented.

**Change route when:** The user/helper identity or device target cannot be verified. · Requested access exceeds the approved session or exposes an active compromise.

### 🎯 Go straight to a specific fix

- **[Move a required file through an approved route](#fix-remote-copy-route-not-proven)** — Screen control works, but the required installer or diagnostic file cannot be transferred.
- **[Restore Mac screen sharing and control](#fix-remote-mac-screen-or-control-permission)** — A <a href="https://github.com/rustdesk/rustdesk/releases/latest" title="Open RustDesk official download or service page" aria-label="Open RustDesk official download or service page" data-inta-brand="rustdesk"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/fd23bf678593f02dcb15.png" alt="RustDesk official page" width="18" height="18" valign="middle" /></a> [RustDesk](https://rustdesk.com/) session connects to a Mac but the screen is blank or input does not work.
- **[Avoid losing the session during a restart](#fix-remote-reboot-needs-a-reconnect-plan)** — The next repair requires rebooting, changing the network adapter or restarting security software.

> [!NOTE]
> **Start here.** Confirm the customer, intended device, and requested task through the established service channel before exchanging a session code.

## Procedure

Work in order, record the result of each step, and change route when the evidence calls for it.

<a id="step-01"></a>

### 01 · Choose the session type

- [ ] For a one-time [Windows](https://www.microsoft.com/windows) session, <a href="https://apps.microsoft.com/detail/9P7BP5VNWKX5" title="Open Microsoft Quick Assist official download or service page" aria-label="Open Microsoft Quick Assist official download or service page" data-inta-brand="quick-assist"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Microsoft Quick Assist official page" width="18" height="18" valign="middle" /></a> [Quick Assist](https://learn.microsoft.com/en-us/windows/client-management/client-tools/quick-assist) offers attended sharing and a separate control request. Use the organization’s approved <a href="https://github.com/rustdesk/rustdesk/releases/latest" title="Open RustDesk official download or service page" aria-label="Open RustDesk official download or service page" data-inta-brand="rustdesk"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/fd23bf678593f02dcb15.png" alt="RustDesk official page" width="18" height="18" valign="middle" /></a> [RustDesk](https://rustdesk.com/) or <a href="https://github.com/Ylianst/MeshCentral" title="Open MeshCentral official download or service page" aria-label="Open MeshCentral official download or service page" data-inta-brand="meshcentral"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4cbfe96e77bec6b7d7f4.png" alt="MeshCentral official page" width="18" height="18" valign="middle" /></a> [MeshCentral](https://meshcentral.com/) deployment for recurring managed support. Cross-platform support needs a tool explicitly supporting both endpoints. Apply [remote capability preflight](https://github.com/Herbertofury/INTA/wiki/Job-remote-support) before choosing: identify who will be present, both operating systems, the required control and file-transfer capabilities, how elevated prompts will be handled, and the approved end state for access. Use the [Tool Selection](https://github.com/Herbertofury/INTA/wiki/Tool-Selection) guide for the decision matrix.

<a id="step-02"></a>

### 02 · Use an official client and the right endpoint

- [ ] Open the tool from the official catalog link or the already managed installation. Confirm the device label with the user and close unrelated sensitive windows. Do not install a second unattended agent merely to avoid fixing an existing approved connection.

<a id="step-prove-the-needed-capabilities-before-repair"></a>

### 03 · Prove the needed capabilities before repair

- [ ] Start in the least-permissive mode that supports the task. Test pointer or view access, a harmless control action if needed, the approved transfer route, and the reconnect plan before changing the machine. <a href="https://apps.microsoft.com/detail/9P7BP5VNWKX5" title="Open Microsoft Quick Assist official download or service page" aria-label="Open Microsoft Quick Assist official download or service page" data-inta-brand="quick-assist"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Microsoft Quick Assist official page" width="18" height="18" valign="middle" /></a> [Quick Assist](https://learn.microsoft.com/en-us/windows/client-management/client-tools/quick-assist) is an attended [Windows](https://www.microsoft.com/windows) path for <a href="https://herbertofury.github.io/INTA/" title="Open INTA official download or service page" aria-label="Open INTA official download or service page" data-inta-brand="app-inta"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/70ad9f0981b05341142b.png" alt="INTA official page" width="18" height="18" valign="middle" /></a> [INTA](https://herbertofury.github.io/INTA/); its <a href="https://support.apple.com/macos" title="Open macOS official download or service page" aria-label="Open macOS official download or service page" data-inta-brand="app-macos"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/c5a768356b120989e4c1.png" alt="macOS official page" width="18" height="18" valign="middle" /></a> [macOS](https://support.apple.com/macos) client and browser support path are restricted to <a href="https://www.microsoft.com/" title="Open microsoft.com official download or service page" aria-label="Open microsoft.com official download or service page" data-inta-brand="site-www-microsoft-com"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="microsoft.com official page" width="18" height="18" valign="middle" /></a> [Microsoft](https://www.microsoft.com/) Support. For <a href="https://remotedesktop.google.com/support" title="Open Chrome Remote Desktop official download or service page" aria-label="Open Chrome Remote Desktop official download or service page" data-inta-brand="chrome-remote-desktop"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4a3cfc17be3f4e8ad2c8.png" alt="Chrome Remote Desktop official page" width="18" height="18" valign="middle" /></a> [Chrome Remote Desktop](https://remotedesktop.google.com/), distinguish the one-use support code from persistent PIN-based access, and keep the user available for renewed sharing confirmation.

**<a href="https://github.com/PowerShell/PowerShell/releases/latest" title="Open PowerShell official download or service page" aria-label="Open PowerShell official download or service page" data-inta-brand="powershell"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="PowerShell official page" width="18" height="18" valign="middle" /></a> [PowerShell](https://learn.microsoft.com/en-us/powershell/) · Inspect Remote Desktop Services state without enabling remote access or opening firewall rules.:**

<a id="step-03"></a>

<a id="03--connect-with-the-user-present"></a>

### 04 · Connect with the user present

- [ ] For <a href="https://apps.microsoft.com/detail/9P7BP5VNWKX5" title="Open Microsoft Quick Assist official download or service page" aria-label="Open Microsoft Quick Assist official download or service page" data-inta-brand="quick-assist"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Microsoft Quick Assist official page" width="18" height="18" valign="middle" /></a> [Quick Assist](https://learn.microsoft.com/en-us/windows/client-management/client-tools/quick-assist), the helper shares the code, the recipient allows screen sharing, and the helper requests control separately. Explain the immediate action before taking control. Let the user enter passwords or handle protected prompts when the tool requires it.

<a id="step-transfer-only-the-files-required-for-this-case"></a>

### 05 · Transfer only the files required for this case

- [ ] Agree on file direction, destination, scope and retention before transfer. Prefer an official publisher download on the target for installers. Use an approved private transfer channel for diagnostic evidence; do not copy unrelated customer folders. <a href="https://github.com/rustdesk/rustdesk/releases/latest" title="Open RustDesk official download or service page" aria-label="Open RustDesk official download or service page" data-inta-brand="rustdesk"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/fd23bf678593f02dcb15.png" alt="RustDesk official page" width="18" height="18" valign="middle" /></a> [RustDesk](https://rustdesk.com/) has a file-transfer permission, while <a href="https://github.com/Ylianst/MeshCentral" title="Open MeshCentral official download or service page" aria-label="Open MeshCentral official download or service page" data-inta-brand="meshcentral"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4cbfe96e77bec6b7d7f4.png" alt="MeshCentral official page" width="18" height="18" valign="middle" /></a> [MeshCentral](https://meshcentral.com/) exposes a separate Files channel. Enable only the needed capability and confirm the actual transfer on the selected clients. The presence of a desktop session alone does not prove the transfer route works.

<a id="step-04"></a>

<a id="04--maintain-a-recovery-path"></a>

### 06 · Maintain a recovery path

- [ ] Before a reboot, adapter change, VPN modification, or security-product restart, confirm how the session will resume and whether someone can act locally. Record work in the private ticket and capture only the evidence needed for the repair.

<a id="step-05"></a>

<a id="05--handle-recurring-access-deliberately"></a>

### 07 · Handle recurring access deliberately

- [ ] For an explicitly managed endpoint, use named technician accounts, the deployment’s access roles, MFA where supported, and a documented device owner. Review existing access rather than sharing one permanent password across coworkers.

<a id="step-06"></a>

<a id="06--close-and-verify"></a>

### 08 · Close and verify

- [ ] Ask the user to perform the original task, end the session, and remove temporary access if it was created only for this case. Confirm any approved persistent agent remains assigned to the correct customer and that the user knows how to contact support again.

<a id="step-leave-evidence-that-access-matches-the-agreement"></a>

### 09 · Leave evidence that access matches the agreement

- [ ] Perform [temporary access revocation](https://github.com/Herbertofury/INTA/wiki/Job-remote-support): close desktop, file and terminal channels; end the support session; remove any one-case unattended credential or temporary enrollment through the approved workflow. Record the ended-session time and access removed, without storing codes or passwords in the ticket. If continuing access is authorized, record its named owner, device group, scope and review date instead. A closed browser tab is not evidence that an installed agent or permanent credential was removed. Use [Service Evidence](https://github.com/Herbertofury/INTA/wiki/Service-Evidence) for the acceptance record.

<a id="acceptance"></a>

<a id="-prove-the-result"></a>

## Verification

- [ ] The intended device was reached and the user’s original task succeeds.
- [ ] The session is ended and temporary access is removed.
- [ ] Persistent access, if requested, has a named owner and correct access scope.
- [ ] The chosen client, platform, user-presence model, transfer route and reconnect behavior were checked before the repair.
- [ ] The transfer record states purpose and destination, and case-only files or access have a documented retention or removal decision.
- [ ] Desktop, file and terminal channels are closed; any continuing access is explicitly owned and authorized.

> [!WARNING]
> **Pause this route and escalate when:**
> - The device or caller identity does not match the service request.
> - The next action could disconnect a critical system without a local recovery path.
> - The requested session would create unattended access, expose files, or use a business plan outside the agreed service scope.
