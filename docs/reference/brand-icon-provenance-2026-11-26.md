# Brand icons: coverage, sources and maintenance

**Acquisition review: November 26, 2026.** The shared icon registry covers all **218 catalog tools** and **644 tool, application, project and website identities**, with **268 distinct cached images**. Repeated mentions reuse the same image bytes. The registry reports no unresolved identity.

## Canonical inputs

| Source | Purpose |
| --- | --- |
| [Brand registry](../../data/brand-icons.json) | Names, precise aliases, tool IDs, hosted acquisition pages, provider URLs and image provenance |
| [Cached images](../../assets/brand-icons/) | Validated PNG files, each identified by its SHA-256 content hash |
| [Runtime helper](../../scripts/brand_icons.py) | Shared resolution, image validation and single-copy embedding for offline use |
| [Refresh command](../../scripts/refresh-brand-icons.py) | Explicit acquisition, validation and safe replacement of publisher assets |
| [Icon regression tests](../../tests/test_brand_icons.py) | Complete catalog and alias coverage, image integrity, offline byte identity and destination correctness |

Each asset records the observed acquisition URL, final response URL, source-image hash, normalized-image hash, publisher host, dimensions and retrieval date. Normalization produces a PNG at no more than 64 pixels per side. This converts or scales an existing identity asset; it does not invent a logo.

## Source choices

**232 distinct assets came directly from publisher websites or existing project assets.** Another **36 are recorded publisher favicons retrieved through Google's favicon cache** where the publisher's direct route was inaccessible or did not expose a usable image. These are clearly identified by `sourceKind` and the exact cache request. The cache provider's generic missing-icon response is rejected.

The application can show a publisher's website icon when a product does not expose a separate app icon. Several products may therefore share the same legitimate publisher identity. This is explicit website identity, not an assertion that each image is a product-specific logo.

## Match the right identity and destination

## Shared-host regression protection

The acquisition review caught and repaired a cache-key error: caching by every URL mentioned in a tool record could associate that tool's icon with a shared release host. The corrected cache keys only the image's recorded publisher identity. Exact tool names still take precedence, while generic <a href="https://github.com/" title="Open GitHub official download or service page" aria-label="Open GitHub official download or service page" data-inta-brand="app-github"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/99f4edb33272b70febb8.png" alt="GitHub official page" width="18" height="18" valign="middle" /></a> [GitHub](https://github.com/) links receive <a href="https://github.com/" title="Open GitHub official download or service page" aria-label="Open GitHub official download or service page" data-inta-brand="app-github"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/99f4edb33272b70febb8.png" alt="GitHub official page" width="18" height="18" valign="middle" /></a> [GitHub](https://github.com/)'s own website icon. An explicit regression test checks this boundary and the suite checks the exact byte identity of every embedded image.

## Refresh on demand

Normal application builds use only the checked-in registry and cached images. They do not contact publishers. The refresh utility uses <a href="https://www.python.org/" title="Open Python official download or service page" aria-label="Open Python official download or service page" data-inta-brand="app-python"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/e3ea97f62e4259df2d67.png" alt="Python official page" width="18" height="18" valign="middle" /></a> [Python](https://www.python.org/) with the `PIL` module, <a href="https://curl.se/windows/" title="Open curl official download or service page" aria-label="Open curl official download or service page" data-inta-brand="curl"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/bfbfbb4fe668dcd07909.png" alt="curl official page" width="18" height="18" valign="middle" /></a> [curl](https://curl.se/) and the `inkscape` executable for SVG conversion.

```sh
python3 scripts/refresh-brand-icons.py
python3 scripts/refresh-brand-icons.py --force --only rufus ventoy
python3 -m unittest discover -s tests -p test_brand_icons.py -v
```

Command legend: <a href="https://www.python.org/" title="Open Python official download or service page" aria-label="Open Python official download or service page" data-inta-brand="app-python"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/e3ea97f62e4259df2d67.png" alt="Python official page" width="18" height="18" valign="middle" /></a> [Python](https://www.python.org/) runs the refresh utility and regression checks. The `PIL` module decodes raster files; <a href="https://curl.se/windows/" title="Open curl official download or service page" aria-label="Open curl official download or service page" data-inta-brand="curl"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/bfbfbb4fe668dcd07909.png" alt="curl official page" width="18" height="18" valign="middle" /></a> [curl](https://curl.se/) applies an absolute request deadline; the installed `inkscape` executable converts an observed SVG to PNG when necessary.

The default command fills missing identities and reuses verified cached assets. `--force` reacquires the selected publishers. Requests have finite wall-clock deadlines, and requests for the same publisher run only once per refresh. Source failures retain the last known complete registry. A refresh with unresolved new identities writes a diagnostic report and returns a failed result instead of exposing a partially populated public registry.

After a successful refresh, inspect the changed images, rebuild the hub and publish the source, cached assets and matching generated surfaces together. The existing complete catalog, aliases, direct downloads and procedure text remain the acceptance boundary.
