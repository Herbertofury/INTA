## 🧭 Match the symptom

| You see this | Do this next | You should get |
| --- | --- | --- |
| **A <a href="https://www.microsoft.com/windows" title="Open Windows official download or service page" aria-label="Open Windows official download or service page" data-inta-brand="app-windows"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Windows official page" width="18" height="18" valign="middle" /></a> [Windows](https://www.microsoft.com/windows) user is present and can approve a session** | Open <a href="https://apps.microsoft.com/detail/9P7BP5VNWKX5" title="Open Microsoft Quick Assist official download or service page" aria-label="Open Microsoft Quick Assist official download or service page" data-inta-brand="quick-assist"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/4538691198fe0ea7526e.png" alt="Microsoft Quick Assist official page" width="18" height="18" valign="middle" /></a> [Microsoft Quick Assist](https://learn.microsoft.com/en-us/windows/client-management/client-tools/quick-assist) on both PCs, exchange the temporary code and have the user approve sharing and any separate control request. | The correct screen is visible and the user understands the control state. |
| **The task requires unattended access or durable audit records** | Use the approved managed tool and existing device identity; verify the technician’s role before connecting. | The session is tied to the intended asset and required audit record. |
| **Elevation or a secure-desktop prompt blocks work** | Have the authorized local user respond or use the approved managed elevation workflow; do not ask for credentials in chat. | The required action is approved without disclosing credentials or bypassing consent. |
| **The repair appears complete** | Repeat the original task with the user, end the session and remove any case-only access setting. | The user confirms the outcome and temporary control has ended. |

### ✅ Finish the job

- [ ] The original task works in the user’s session.
- [ ] The session is closed and authorized persistent access is documented.

**Change route when:** The user/helper identity or device target cannot be verified. · Requested access exceeds the approved session or exposes an active compromise.
