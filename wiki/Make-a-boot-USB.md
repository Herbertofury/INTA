## ⚡ First three actions

1. Download the correct image and check its published checksum or signature where supplied.
2. In <a href="https://rufus.ie/#download" title="Open Rufus official download or service page" aria-label="Open Rufus official download or service page" data-inta-brand="rufus"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/45e3e333ec681715ba99.png" alt="Rufus official page" width="18" height="18" valign="middle" /></a> [Rufus](https://rufus.ie/), confirm the USB model and capacity, select the ISO and choose the target’s firmware-compatible options.
3. Write the USB, check the log and test that it boots before taking it to the client.

## 🧭 Match the symptom

| You see this | Do this next | You should get |
| --- | --- | --- |
| **Only one rescue or installation image is needed** | Use the official ISO and <a href="https://rufus.ie/#download" title="Open Rufus official download or service page" aria-label="Open Rufus official download or service page" data-inta-brand="rufus"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/45e3e333ec681715ba99.png" alt="Rufus official page" width="18" height="18" valign="middle" /></a> [Rufus](https://rufus.ie/); confirm the selected USB can be erased and choose firmware-compatible options. | The intended image is written to the correct device. |
| **Several verified images must stay on one USB** | Use the documented <a href="https://www.ventoy.net/en/download.html" title="Open Ventoy official download or service page" aria-label="Open Ventoy official download or service page" data-inta-brand="ventoy"><img src="https://raw.githubusercontent.com/Herbertofury/INTA/main/assets/brand-icons/d1a0c38643bc2cdb9425.png" alt="Ventoy official page" width="18" height="18" valign="middle" /></a> [Ventoy](https://www.ventoy.net/) install/update path and copy the checked images to its data partition. | The expected images appear in the boot menu. |
| **The publisher supplies a checksum** | Run Get-FileHash for the exact downloaded file and compare it with the official value before writing. | The calculated hash matches the trusted release record. |
| **Writing finished but the client may have unusual hardware** | Boot-test the intended firmware mode and verify keyboard, storage, network and the required recovery tool. | The actual service path works on representative hardware rather than only completing an image write. |

### ✅ Finish the job

- [ ] Image source, hash and release are recorded.
- [ ] The USB boots and detects the hardware required for the planned job.

**Change route when:** The target USB or its erase permission is uncertain. · A firmware/security change lacks the necessary recovery material.
